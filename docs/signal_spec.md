# 売買シグナル仕様 (signal_spec.md)

『わが投資術』から抽出した102ルール(`investment_rules.md`)を、J-Quants日次CSVで機械判定できるものとできないものに分類し、判定できるものを買い/売りシグナル条件として仕様化する。
`implementation_notes.md` の方針(ロングオンリー、二段階=数値フィルタ→定性評価、価格ベースの損切り/利確はしない、売買の最終判断は人間)に従う。

【推測】は本文にない閾値で、仕様上の仮置き値。バックテストか本人の裁量で決める。

---

## 1. 結論と、先に決めるべきこと

1. **日次CSV(株価・出来高・時価総額)だけで判定できるルールは102件中9件**。本書の中核である割安判定(ネットキャッシュ、キャッシュニュートラルPER)には**財務データが必須**で、CSVには入っていない。
2. 財務データを足せば、判定できるルールは**A+Bの35件**に増える。シグナルの中心は「割安の買い候補」。
3. 本書の手法は「売買頻度が低い」ので、日次CSVの用途は **①買いの見送り判定 ②急落アラート ③時価総額の計算** に限られる。本文はテクニカル指標によるシグナル生成を明確に避けており、チャートから買い/売りは出さない。
4. 売りは価格では決まらない。「役割終了」「割安条件の崩壊」「仮説棄却」の3つで決め、**売りボタンは人間が押す**(システムは「売り検討」を出すだけ)。

## 4. シグナル仕様

### 4.0 共通の約束
- 株価は**調整後(`AdjC`, `AdjVo`)**で計算する(分割の影響を避ける)。
- `UL=1` の日は、その銘柄の買いシグナルを「執行不可」として出す。
- シグナルは「候補」「見送り」「アラート」「売り検討」の4種類。**買い/売りは人間がボタンで確定**する。
- 損切り(◯%下落で売る)と、利確(◯%上昇で売る)は実装しない(TR-04、TR-16)。

### 4.1 S1: 買い候補 `BUY_CANDIDATE`(B。SC-01の再現)
四半期ごと(数カ月に1回)に全銘柄へ適用し、ネットキャッシュ比率の降順で出力する。

| # | 条件 | 出典 | 区分 |
|---|---|---|---|
| 1 | 市場区分が スタンダード/プライム。グロースは除外 | SC-02, SC-03 | B |
| 2 | 時価総額 20億円以上。スタンダードは500億円未満、プライムは3000億円未満 | VA-16, SC-02 | A |
| 3 | `net_cash = 流動資産 + 投資有価証券×0.7 − 総負債` が 0 以上 | VA-03, VA-06 | B |
| 4 | `nc_ratio = net_cash / 時価総額` を計算 | VA-04 | B |
| 5 | `cn_per = PER × (1 − nc_ratio)` が **10以下**。`nc_ratio ≥ 1` は定義不能として「極端に割安」フラグ | VA-05, VA-08 | B |
| 6 | 黒字継続:直近3期のうち赤字が2期以上なら除外【推測】 | VA-12 | B |
| 7 | 不動産業は自己資本比率30%以上を優先、20%未満は除外 | VA-17, SC-05 | B |
| 8 | 電気・ガス・鉄道は配当利回りの閾値で判定(閾値は未定)。満たさなければ除外 | VA-20 | B |
| 9 | 上場後3年未満は除外【推測】 | VA-15, SC-06 | B |
| 10 | S2(買い見送り)に該当しない | TR-01 | A |

出力に併記する:`nc_ratio`、`cn_per`、織り込み成長率 `a = (1+r)(1−1/PER)`(金利 r=2〜3%)(VA-09)、増配余地の目安(配当性向が低い=加点、VA-19)。
**この時点では「買え」ではない**。次に人間とAI(C分類)が「なぜ低評価か」「成長仮説があるか」を確認し、人間が買いボタンを押す。

注意:`PER` が使えるのは黒字銘柄のみ。PERの元になる当期純利益は、実績ではなく**予想**と**正常化EPS**(過去3〜5期の平均【推測】、VA-14)の両方を出して見比べる。

### 4.2 S2: 買い見送り `BUY_BLOCKED`(A)
次のいずれかなら、その日は買わない(TR-01、SC-06)。

- `AdjVo` の20日平均 ÷ 120日平均 **> 2** かつ `AdjC` が過去60日高値の **95%以上**【推測】
- `UL = 1`(ストップ高。執行不可)

下落率が大きいことは見送りの理由にも、割安の根拠にもしない(VA-18)。

### 4.3 S3: 個別急落アラート `SHOCK_ALERT`(A+C)
対象は保有銘柄とウォッチリスト(TR-11、PH-16)。

- 発動:前日比 **−15%以下** かつ 出来高が20日平均の **3倍以上**【推測】(または `LL=1`)
- 動作:アラートを出し、その銘柄がS1の条件(割安さ)を今も満たすか再計算する。満たす場合は `BUY_ZONE`(買い場候補)を付ける。
- 事業価値が毀損したかはC分類(適時開示をAIが要約)+人間が判断する。

### 4.4 S4: 相場急落アラート `MARKET_CRASH_ALERT`(A)
- **TOPIXはCSVに無い**ので、全銘柄の時価総額加重の騰落率で代用する(TOPIXの代替データを入れたら置き換える)。
- 発動:5営業日で **−10%以下** かつ 全市場の売買代金(`Va`合計)が過去60日平均の **2倍以上**【推測】(TR-08、TR-14、MK-02)
- 動作:ウォッチリスト全銘柄を再計算し、S1の条件を満たすものを「一括買い候補」に出す。**売りシグナルには使わない**(TR-09:底打ち確認を待たない)。
- 本文の注意:TOPIXが5%下がっても5%以上下がる割安小型株はほとんど無い(TR-14)。

### 4.5 S5: 売り検討 `SELL_REVIEW`(B、一部X)
四半期ごとの見直しで保有銘柄に適用する。**価格の上げ下げでは出さない**。

| トリガ | 条件 | 出典 | 区分 |
|---|---|---|---|
| 役割終了 | `cn_per` が20〜30以上になった【推測】 | TR-05 | B |
| 役割終了 | アナリストカバー数が3以上、または機関投資家保有の増加 | TR-05 | **X**(データ待ち) |
| 割安条件の崩壊 | 赤字化、またはネットキャッシュがマイナス(ネットデット化) | TR-16の趣旨, VA-06, VA-12 | B |
| 仮説棄却 | 人間が入力する | TR-06 | D |

**保有ガード `HOLD_GUARD`(G)**:買値から上昇率が +100%未満 かつ 保有3年未満 かつ 仮説が維持されているなら、役割終了トリガ以外の売りは出さない(TR-04)。

### 4.6 S6: ポートフォリオ・ガード(G)
違反を検知したら警告を出す(売買の強制はしない)。

| ガード | 条件 | 出典 |
|---|---|---|
| 1銘柄の上限 | ウェイト ≤ 25% | PF-01 |
| 銘柄数 | 7〜10銘柄 | PF-03 |
| 投資比率 | ≤ 50〜75%(暴落時の買い余力) | PF-05, PH-11 |
| 信用取引 | 0(レバレッジなし) | PF-06 |
| 発注量 | 1日の発注 ≤ 日次出来高の10%【推測】。時価総額50億円程度の銘柄では約2億円が上限の目安 | TR-03 |
| 大量約定の警告 | 想定より大量に約定した場合 | TR-10 |

### 4.7 S7(任意): 期初予想の保守性 `GUIDANCE_CONSERVATIVE`(B)
過去の「実績 ÷ 期初予想」の平均が1.1超の会社を抽出し、期初予想の発表後に下落したら買い候補、2Qの通期予想に対する進捗率が50%を超えたら売り検討に加える【推測】(GR-08)。本文は一事例(プレサンス)からの一般化なので優先度は低い。

## 5. 実装順序(提案)

1. **日次CSVだけで先に作れるもの**:S2(買い見送り)、S3(個別急落)、S4(相場急落)、時価総額区分。財務データを待たずに動く。
2. **財務・マスター取得**:ネットキャッシュ、PER、市場区分。取得できたらS1とS5(PER部分)を作る。
3. **ガード**:S6はポートフォリオの保有データが入ってから。
4. **後回し**:アナリスト数、裁定残高、空売り残高(Xの項目)。
